# 캐시로그 (CashLog)

**1인 개인사업자를 위한 가계부 겸 자금관리 장부.**
사업 돈과 생활비가 한 통장에 섞여 있는 자영업자가, 매일 1~2분 입력만으로
"이번 달 사업으로 얼마를 벌었고, 사업에 얼마를 썼고, 생활비로 얼마가 나갔고, 실제로 얼마가 남았는지"를
정확하게 볼 수 있게 만든 웹 서비스입니다.

[![CI](https://github.com/sde0110/CashLog/actions/workflows/ci.yml/badge.svg)](https://github.com/sde0110/CashLog/actions/workflows/ci.yml)

> **설계 철학 — 돈이 나갔다고 모두 비용이 아니고, 돈이 들어왔다고 모두 수입이 아니다.**
>
> 통장 → 예금, 현금 인출, 카드대금, 예·적금 만기 원금, 대여금 회수 같은 돈의 이동은
> 수입도 지출도 아닙니다. 일반 가계부는 이것을 수입·지출로 잡아 숫자를 부풀리지만,
> 캐시로그는 모든 거래에 **성격(수입 / 지출 / 이체)** 을 부여하고 이체는 모든 집계에서 뺍니다.

## 1. 어떤 서비스인가

### 해결하려는 문제

학교 납품·설치를 하는 1인 사업자의 실제 장부에서 출발했습니다. 기존에는 네이버 가계부를 썼는데,
다음 문제들 때문에 "사업이 실제로 얼마나 남는지"를 알 수 없었습니다.

| 문제 | 예 |
|---|---|
| 회사 돈과 가계 돈이 섞인다 | 사업통장에서 집으로 보내는 월 생활비가 "주거/공과금"으로 잡힘 |
| 자금이동이 비용으로 잡힌다 | 부가세 통장으로 옮긴 돈, 적금 납입, 주식계좌 이체가 지출로 집계됨 |
| 자금이동이 수입으로 잡힌다 | 적금 만기 원금, 대여금 회수가 수입으로 집계됨 |
| 매입과 세금이 섞인다 | 거래처 매입비와 부가세 납부가 같은 분류 |
| 사장님께 설명하기 어렵다 | 매출은 커 보이는데 실제로 남은 돈을 한 장으로 보여줄 수 없음 |

### 누가 쓰나

- **주 사용자**: 경리 업무를 보는 가족(50~60대). 회계 지식이 없어도 쓸 수 있어야 한다.
- **보조 사용자**: 사업자 대표. 월간 보고 화면 한 장으로 현황을 본다.

그래서 화면은 네이버 가계부처럼 익숙한 형태(월 요약 → 날짜별 내역 → 달력 → 분석)를 따르고,
글자와 버튼을 크게, 회계 용어(차변·대변)는 사용자에게 묻지 않고 시스템이 자동으로 처리합니다.

### 무엇이 아닌가

세무신고 프로그램이 아닙니다. 세무신고는 세무대리인이 하고, 캐시로그는 **내부 자금 흐름을 정확히
기록하고 근거 자료(분개장·시산표)를 만드는 것**까지 합니다. 은행·카드 자동 연동은 보안·비용 문제로
의도적으로 하지 않고, 빠른 수동 입력에 집중합니다.

## 2. 주요 기능

### 📒 가계부 (첫 화면)
- **월 요약**: 수입 · 지출 · 남은 돈 + 사업비 / 세금 / 생활비(가계이체) / 이체(제외됨) 내역
- **계산 방법 보기**: 지출 합계가 어떻게 나왔는지 실제 숫자로 펼쳐 보여줌
- **내역**: 날짜별로 묶은 거래 목록과 일별 합계
- **달력**: 날짜마다 수입·지출 표시, 날짜를 누르면 그날 내역과 "이 날짜로 입력"
- **분석**: 분류별 지출 · 결제수단별 지출 · 분류별 수입 · 이체 내역 막대그래프
- 이번 달 고정지출을 아직 안 넣었거나, 미입금 매출이 있으면 알림 카드

### ✏️ 거래 입력
- 상단 탭 **지출 / 수입 / 이체** → 금액 → 분류 → 결제수단 순서
- 분류는 묶음별 칩: 지출은 *사업비 · 생활비(가계이체) · 세금 · 기타지출*, 수입은 *사업매출 · 기타수입*
- **결제수단**을 종류별로 구분: 체크카드(동백전·오륙도) / 신용카드 / 페이(네이버·카카오·KB) / 현금 / 통장.
  지난번에 쓴 결제수단을 기억해 미리 선택
- **부가세 자동 안분**: 사업 거래는 금액 하나만 넣으면 공급가액·부가세를 자동 계산 (10% 포함 / 없음 / 직접)
- **만기 처리**: 예금·적금 만기를 고르면 이자 칸이 나타나고, 원금은 이체 · 이자는 금융수입으로 2건 자동 생성
- **"매달 나가는 고정지출이에요"** 체크 시 고정지출 템플릿도 함께 등록
- 저장 전 확인: 큰 금액(기준액 이상), 같은 날 같은 금액 거래(중복 의심)
- 삭제 후 **되돌리기** (soft delete)
- 빠른 금액 버튼(+1만 · +5만 · +10만 · +100만), "저장 후 계속 입력"

### 🏦 자산
- 통장 · 현금 · 저축/투자 · 기타자산의 잔액 (기초잔액 + 입금 − 출금)
- 체크카드·페이에 "연결 통장"을 지정하면 그 통장 잔액에서 차감
- **잔액 맞추기**: 실제 통장 잔액을 넣으면 기초잔액을 역산해 맞춤 (거래 기록은 그대로)
- 카드·페이별 이번 달 사용액

### 📊 보고서
- **사장님 월간 보고**: 한 줄 요약 문장, 매출·사업비·세금·가계이체·실제 지출·순현금흐름(전월 대비),
  사업비 TOP 5, 거래처별 지출, 학교별 매출, 생활비 내역, 미입금 매출. 인쇄·PDF 레이아웃 지원
- **연간 보고**: 연간 합계와 월평균(거래가 있는 달 수 기준), 월별 수입·지출 차트,
  항목별 합계·월평균 — 체크를 풀면 그 항목(일회성 비용)을 뺀 월평균을 함께 계산
- **학교(프로젝트)별 손익**: 매출 − 사업비
- **분개장 · 합계잔액시산표**: 분류와 결제수단으로 자동 작성한 복식부기 장부. 대차 일치 검증

### 🔁 고정지출
- 관리비 · 보험료 · 세무사 수수료 · 매달 가계이체처럼 매달 같은 날 반복되는 거래를 등록
- 매달 확인 후 **[○월에 넣기]** 한 번으로 해당 월 거래 생성 (자동으로 넣지 않음, 같은 달 중복 생성 방지)

### 🔍 검색
- 기간 · 수입/지출/이체 · 대분류 · 세부분류 · 결제수단 · 거래처 · 학교 · 금액 범위 · 태그 · 미입금 · 키워드
- 검색 결과 합계, **여러 건 선택 후 결제수단·분류 일괄 변경 / 삭제**

### ⚙️ 설정
- 결제수단·계좌 (종류, 연결 통장, 기초잔액, 숨기기)
- 분류 (아이콘·이름·설명, 추가/숨기기 — 성격은 변경 불가)
- 거래처 · 학교/프로젝트 · 사업자 정보 · 큰 금액 기준 · 부가세율 · 중복 경고
- **데이터 가져오기**: 네이버 가계부 CSV, 구버전(구글시트) 엑셀 — 여러 번 올려도 중복 없음
- **백업**: 전체 거래 CSV 내려받기 (엑셀 호환)

### 이전 버전

시트 전체를 읽어 느리고(저장 확인까지 수 초), 동시성·검색·확장에 한계가 있어 지금 구조로 옮겼습니다.
분류 체계와 집계 규칙은 그대로 이어받았고, 기존 데이터는 가져오기 기능으로 옮깁니다.

## 4. 시스템 구성

```
 브라우저 (휴대폰 · PC)
    │  HTTPS
    ▼
 Vercel ─ proxy.ts ──────── 세션 쿠키 검사 (없으면 /login)
    │
    ├─ 서버 컴포넌트 ─────── 화면 렌더링: 조회 쿼리 → 순수 함수로 집계 → HTML
    │
    └─ Server Actions ───── 저장 · 수정 · 삭제 · 가져오기 (각 액션이 다시 인증 확인)
             │
             ▼
     Neon Postgres (sin1) ── Drizzle ORM, HTTP 드라이버
```

- **집계·분개는 순수 함수**(`src/lib/ledger.ts`, `src/lib/journal.ts`)로 분리되어 DB 없이 테스트됩니다.
- 거래 저장은 서버 액션 한 번의 왕복(검증 → 경고 확인 → INSERT)으로 끝나며, 저장 후 `revalidatePath` 로 화면이 갱신됩니다.
- 기초정보(계좌·분류·거래처)는 요청당 한 번만 읽고(`React.cache`) 클라이언트에 내려 입력 화면에서 즉시 사용합니다.

## 5. 핵심 규칙 — 분류와 집계

### 분류 체계

모든 거래는 **대분류 → 세부분류** 를 가지며, 세부분류가 **성격(flow)** 을 결정합니다.
클라이언트가 보낸 값은 믿지 않고 서버가 분류에서 다시 읽습니다.

| 대분류 | 성격 | 예 |
|---|---|---|
| 사업매출 | 수입 | 학교납품 · 설치비 · 용역비 · 상품판매 |
| 사업비 | 지출 | 상품매입 · 외주/설치비 · 지급수수료 · 차량유지비 · 업무추진비 |
| 세금 | 지출 | 부가가치세 · 종합소득세 · 자동차세 · 과태료/범칙금(구분 조회) |
| 가계이체 (생활비) | 지출 | 정기가계이체 · 식비 · 주거/공과금 · 의료 · 교육 … — **사업비와 절대 섞지 않음** |
| 자금이동 (이체) | **중립** | 계좌간이동 · 현금인출 · 카드대금결제 · 부가세통장이체 · 예적금 · 투자 · 대여금 · 보증금 |
| 기타 | 수입/지출 | 금융수입 · 보험보상금 · 세금환급 (매출 아님) / 기타지출 |

### 집계 공식

```
실제 수입   = 사업매출 + 기타수입
실제 지출   = 사업비 + 세금 + 기타지출            ← 이체·가계이체 제외
전체 출금   = 실제 지출 + 가계이체 + 자금이동
순현금흐름  = 실제 수입 − 실제 지출 − 가계이체
예상 부가세 = 매출 부가세 − 매입 부가세
```

`실제 지출 = 전체 출금 − 자금이동 − 가계이체` 가 항상 성립하는지 테스트로 검증합니다.
연간 월평균은 **거래가 있는 달 수**로 나눠, 아직 오지 않은 달 때문에 평균이 희석되지 않게 합니다.

### 결제수단과 이체

- 카드·페이로 쓴 돈은 **쓸 때** 지출로 잡힙니다. 카드대금이 통장에서 빠질 때는 *이체 › 카드대금결제* 로 적어 이중 집계를 막습니다.
- 통장에서 현금을 뽑으면 *이체 › 현금인출*, 그 현금으로 쓰면 결제수단 *현금* 으로 적습니다.

### 복식기장 (자동 분개)

사용자는 차변·대변을 입력하지 않습니다. 분류의 계정과목과 결제수단 종류로 분개가 만들어집니다.

```
수입      차) 보통예금          총액     대) 상품매출/용역매출   공급가액
                                         대) 부가세예수금        부가세
지출      차) 비용계정        공급가액   대) 보통예금 / 미지급금(신용카드)  총액
          차) 부가세대급금      부가세

```

미입금 매출은 보통예금 대신 **외상매출금**, 사업주 개인 용도(가계이체·소득세)는 비용이 아닌 **인출금**입니다.
세무상 최종 판단은 세무대리인이 합니다.

### 네이버 가계부 가져오기 규칙

- 전월이월(통장잔고·○○은행잔고이체)은 **수입이 아니라 통장 기초잔액**
- 태그에 적힌 결제수단(동백·부산체크·KBpay·우카 …)을 실제 결제수단으로 연결
- 거래처 매입 → 사업비, 주유 → 차량유지비, "급여" 이체 → 정기가계이체, 생활 지출 → 가계이체 세부분류
- 원본 CSV 합계와 변환 합계가 1원 단위까지 일치하는지 테스트로 검증
- 행마다 `source_key` 를 만들어 **몇 번을 다시 가져와도 중복되지 않음**

## 7. 보안

| 항목 | 구현 |
|---|---|
| 인증 | 단일 비밀번호(`APP_PASSWORD`) → HMAC-SHA256 서명 쿠키(HttpOnly · Secure · SameSite=Lax, 30일) |
| 세션 무효화 | 서명에 비밀번호를 포함 — 비밀번호를 바꾸면 모든 기기의 로그인이 풀림 |
| 무작위 대입 차단 | 시도를 먼저 기록한 뒤 횟수를 세어 동시 요청으로도 우회 불가. 15분 10회 / 하루 30회 초과 시 잠금 |
| 이중 인증 확인 | `proxy.ts` 가 모든 페이지를 막고, 모든 Server Action · API 가 다시 세션을 확인 |
| 리다이렉트 | 로그인 후 이동 주소는 사이트 내부 경로만 허용 (`//`, `/\` 차단) |
| SQL | Drizzle 파라미터 바인딩만 사용 |
| 보안 헤더 | `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `noindex` |
| CSV 내보내기 | `=`, `+`, `-`, `@` 로 시작하는 글자는 엑셀 수식으로 실행되지 않게 처리 |
| 비밀 정보 | DB 주소·비밀번호는 Vercel 환경변수에만 존재. 저장소·클라이언트 번들에 포함되지 않음 |
| 개인 데이터 | 실제 금융 데이터(`data/`)는 저장소에 올리지 않음. 테스트는 가짜 데이터(`tests/fixtures`) 사용 |

## 8. CI/CD

```
 git push / PR
    │
    ├─▶ GitHub Actions (ci.yml)
    │     1. npm ci
    │     2. 타입 검사          npm run lint
    │     3. 단위 테스트        npm test
    │     4. 마이그레이션 누락 검사   schema.ts 를 바꾸고 db:generate 를 안 했으면 실패
    │     5. 프로덕션 빌드      npm run build (DB 없이)
    │
    └─▶ Vercel (Git 연동)
          · PR / 다른 브랜치 → 미리보기 배포 (Vercel 로그인으로 보호)
          · main            → 운영 배포
                               빌드 단계에서 scripts/migrate.ts 가 DB 마이그레이션 + 기본 데이터 적용
```

- 미리보기 배포는 운영 DB 를 함께 쓰므로 **마이그레이션은 운영 배포에서만** 실행됩니다.
  스키마를 바꾸는 PR 은 이전 스키마와도 호환되게(컬럼 추가 위주로) 작성하세요.
- 마이그레이션은 drizzle 이 적용 이력을 기록하므로 여러 번 실행해도 안전합니다.
- 문제가 생기면 Vercel 대시보드에서 이전 배포로 즉시 되돌릴 수 있습니다(Instant Rollback).

### 환경변수 (Vercel)

| 이름 | 설명 |
|---|---|
| `DATABASE_URL` | Neon 연결 주소 — Marketplace 연동 시 자동 등록 |
| `APP_PASSWORD` | 로그인 비밀번호 |
| `SESSION_SECRET` | 세션 서명 키 (`openssl rand -base64 48`) |

비밀번호 변경: `vercel env add APP_PASSWORD production --force` → 재배포.

## 9. 로컬 개발

```bash
npm install
vercel link                         # Vercel 프로젝트 연결 (최초 1회)
vercel env pull .env.local --yes    # DATABASE_URL · APP_PASSWORD · SESSION_SECRET
npm run db:migrate                  # 스키마 + 기본 분류·결제수단
npm run dev                         # http://localhost:3000
```

| 명령 | 하는 일 |
|---|---|
| `npm test` | 단위 테스트 |
| `npm run lint` | 타입 검사 |
| `npm run db:generate` | `src/db/schema.ts` 변경 → SQL 마이그레이션 생성 (커밋 필요) |
| `npm run db:migrate` | 마이그레이션 적용 |
| `npm run import:naver [폴더]` | 폴더 안의 네이버 가계부 CSV · 구글시트 xlsx 를 DB 로 가져오기 |
| `tsx scripts/reclassify-naver.ts` | 가져오기 분류 규칙을 고친 뒤 기존 거래에 다시 적용 (사용자가 고친 거래는 건너뜀) |
